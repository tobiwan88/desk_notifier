# Hardware: where to look

There is one KiCad project: **`notifier-v1/notifier-v1.kicad_pro`** (schematic + PCB).
Open it with `hardware/open.sh`, or File > Open Project in KiCad. Everything else is generated.

| What | Where |
|---|---|
| KiCad project (schematic, PCB) | `notifier-v1/` |
| Board profile (notes, rules the scripts check, datasheet cards) | `notifier-v1/BOARD.md`, `board.yaml`, `critical.yaml`, `parts/` |
| Order checklist, bring-up | `notifier-v1/ORDER.md` |
| Design notes, toolchain, lessons | `PLAN.md` |
| Review images (annotated renders, layers, 3D, schematic tiles) | `out/review/notifier-v1/` (after a pipeline run) |
| JLCPCB upload files (gerbers zip, BOM, CPL) | `out/fab/notifier-v1/` (after a pipeline run) |
| Router logs | `out/route/` |
| Board-neutral checks (critical blocks, regulator, impedance) | `calc/` (each takes the board folder) |
| Generators (edit these, not the KiCad files) | `gen/notifier_v1.py` (schematic), `gen/layout_v1.py` (placement) |

The KiCad files are regenerated by `tools/pipeline_v1.sh`: edits made in KiCad are overwritten on the
next run. Review in KiCad, then change the generators. `out/` is not in git; `tools/setup_tools.sh`
installs the routers once.

Agent skills (board-neutral): `hw-base` (read first), `kicad-schematic`, `kicad-layout`, `hw-parts` in `.claude/skills/`.
